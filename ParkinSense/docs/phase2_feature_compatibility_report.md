# Phase 2 Feature Compatibility Report

Audit date: 2026-10-15

## Summary decision

The three domains share a 72-channel naming layout and the same downstream summary-statistic code in some paths, but the inspected code does not establish that their channel values are equivalent measurements. DNE, MediaPipe, and 4D-Humans must **not** be combined for supervised training or treated as interchangeable model inputs based only on matching column names. The Phase 2 candidate is TULIP-only and preserves MediaPipe-extracted features; no cross-domain data was created.

## Common output calculation

`src/features/smpl_feature_extractor.py` takes a sequence of 24 3x3 rotation matrices, converts the pelvis `global_orient` and 23 `body_pose` joints to 72 three-component axis-angle values with `scipy.spatial.transform.Rotation.from_matrix(...).as_rotvec()`, then computes population mean, population standard deviation, minimum, and maximum over the available frames for each component. This yields 288 pose statistics.

The same helper sets `fps` from the caller-supplied rate and `num_frames` to the number of rows passed to the extractor. The 290-column contract puts these two metadata values before the pose statistics. Matching this contract validates shape/order/finiteness; it does not validate that upstream pose estimators measure the same underlying quantities.

## Metadata columns

- `fps` is acquisition metadata, not a gait measurement. DNE reads it from trial metadata; the video pipelines read container metadata (or use a fallback). The clinical TULIP files are approximately 80 FPS, while the application paths may process videos with different rates. It should not be used as a classifier feature without a separate, justified temporal resampling/normalization design.
- `num_frames` is a count of different row populations: DNE pose samples, MediaPipe frames with accepted landmarks, or rows in the selected HMR2 tracklet. These counts depend on recording duration, model detection/tracking, and sampling. It should not be treated as a clinical gait feature.
- The candidate retains both fields for provenance and audit only. Any future training feature selector must explicitly exclude them unless the protocol justifies otherwise.

## Measurement mismatches and limits

1. DNE code summarizes a stored 72-channel `pose` array directly. The inspected builder does not establish whether it has the same per-frame representation, SMPL joint order, handedness, coordinate axes, and root/local reference conventions as the inferred values from either video pipeline.
2. MediaPipe constructs SMPL-like rotations from sparse visual landmarks; HMR2 predicts SMPL rotations from detected image crops and selects one tracked person. Shared joint labels do not remove estimator-specific bias, visibility/fallback behavior, camera-view effects, or differences in the tracked frame set.
3. The normalized DNE builder zeros root channels 0-2; the standard 290-feature extractor does not. This is an explicit representation mismatch between normalized DNE data and standard application features.
4. The summary statistics operate on axis-angle components, including component-wise mean/min/max. Their interpretation can be sensitive to axis-angle representation and wraparound; the code does not canonicalize those statistics across estimators or coordinate frames.
5. The 44-row clinical TULIP source features were produced with the MediaPipe extraction path/cache. Their `fps` values are near 80 and the feature table records detected frames. The separate extraction audit indicates cached extraction success; this audit did not rerun video extraction.

## Safe Phase 2 use and next evidence needed

The new 43-row file is restricted to the verified clinical TULIP subset with one identity-ambiguous video excluded. It may be used as a standalone, exploratory TULIP-only dataset after Phase 3 authorization. Its 8 participants are the grouping unit. It must not be concatenated with the 322-row DNE table or used as evidence that the production MediaPipe and 4D-Humans pipelines share a calibrated classifier.

Before cross-domain training or production integration, establish authoritative joint/channel mapping and coordinate-frame conventions from the DNE source, quantify estimator/domain differences on matched recordings or a validated bridging set, and verify the exact application extractor output against the proposed model's trained representation. No changes to production prediction behavior are warranted by the Phase 2 evidence.
